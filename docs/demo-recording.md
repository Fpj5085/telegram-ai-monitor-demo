# 终端 Demo 录制方案

仓库目前没有附截图或 GIF：可验证的素材是实际执行的命令和测试回执，不把排版图伪装成运行画面。可在干净的终端窗口按下列脚本录制真实运行，约 40–55 秒。

## 录制前

1. 使用 Python 3.11 或 3.12，打开仓库目录下的新终端。
2. 只展示仓库名和命令，不打开原项目、OpenClaw 数据目录、真实配置或生产日志。
3. 清屏后开始录屏；不要录入账号、密钥或个人路径。

## 40–55 秒镜头顺序

| 时间 | 终端动作 | 讲解重点 |
|---|---|---|
| 0–5 秒 | 显示 `python -m telegram_ai_monitor_demo demo` | 这是全离线演示，fixture 与微信接口均为模拟。 |
| 5–12 秒 | 展示 `[1/7]` 和采集后的 SQLite 摘要 | 规则从 5 条合成消息中筛选并将候选写入 SQLite。 |
| 12–20 秒 | 展示 `[2/7]`、`business_code: -2` 与熔断状态 | 失败被区分为业务拒绝；日报、队列保留。 |
| 20–26 秒 | 展示 `[3/7]` 同版本重启和累计请求数仍为 1 | 状态存在 SQLite，新进程没有再次请求接口。 |
| 26–36 秒 | 展示 `[4/7]` 版本改变，日报先补发、再发送一条告警 | 日报复用已有内容；不生成日报、不调用模型。 |
| 36–44 秒 | 展示 `[5/7]` 限速与 `[6/7]` 后续模拟分钟 | 模拟时间验证每分钟最多一条告警。 |
| 44–55 秒 | 展示最终 SQLite 状态、`[7/7] temporary_state_cleaned=True`，再运行 `python -m unittest discover -s tests -v` | 临时状态清理，测试覆盖跨进程与并发边界。 |

## 可复现命令

```powershell
python -m telegram_ai_monitor_demo demo
python -m unittest discover -s tests -v
```

录制后可从真实运行视频截取日报/队列状态和重启阻断两个画面。分享前检查画面中没有本机绝对路径或其他窗口内容。不要把本方案中的时间线当作测试回执；测试回执以实际命令输出为准。
